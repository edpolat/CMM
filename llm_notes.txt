The SDK provides several essential methods:
• get_logits_from_input_ids(input_ids: List[int]) -> List[float]
Takes a list of token IDs and returns the logits produced by the LLM model.
• get_path_to_vocab_file() -> str
Returns the path to the vocabulary file containing the correspondence between
token IDs and tokens.
• encode(text: str) -> Tensor
Encodes a text string into a tensor of token IDs using the model’s tokenizer.
• decode(token_ids: List[int]) -> str (optional)
Optionally decodes a list of token IDs back into a text string.

Trie (Prefix Tree) nedir?
Trie, kelimeleri ortak önekleri (prefix) paylaşacak şekilde bir ağaç yapısında saklayan 
bir veri yapısı. Adı "retrieval" kelimesinden geliyor.
Neden buna ihtiyacımız var
Elimizde şu fonksiyon isimleri var (senin functions_definition.json'undan):

￼

fn_add_numbers
fn_greet
fn_reverse_string
fn_get_square_root
fn_substitute_string_with_regex
Model, bu isimlerden birini token token üretecek. 
Her adımda sana soru şu: 
"Şu ana kadar ürettiğim metin parçası (örn. 'fn_g'), bu 5 isimden en az birinin başlangıcı mı?
Eğer öyleyse, bir sonraki token olarak hangi tokenler mantıklı olur?"
Basit ama yavaş bir yaklaşım (trie olmadan)
Aslında trie olmadan da bunu yapabilirsin — her adımda, şu ana kadar ürettiğin string'i alıp, 
tüm 5 ismin başına uyuyor mu diye tek tek str.startswith(...) ile kontrol edebilirsin

Peki trie ne zaman gerçekten işe yarar
Asıl kritik nokta şu: Sen aslında karakter bazında değil, token bazında ilerliyorsun. 
Yani "fn_add_numbers" kelimesi tek bir string değil, birden fazla token'a bölünmüş olabilir 
("fn", "_add", "_numbers" gibi — gerçek bölünme tokenizer'a bağlı). Senin çözmen gereken 
asıl problem şu:
"Şu ana kadar ürettiğim token dizisi (ID listesi), decode edildiğinde bir fonksiyon isminin 
başlangıcına denk geliyor mu? Eğer öyleyse, vocab'daki 151.643 token'dan hangileri, bu diziye 
eklendiğinde hâlâ geçerli bir başlangıç olmaya devam eder?"

Somut örnek — trie'ın görünümü
(kök)
 └── f
      └── n
           └── _
                ├── a → d → d → _ → n → u → m → b → e → r → s (son: fn_add_numbers)
                ├── g
                │    ├── r → e → e → t (son: fn_greet)
                │    └── e → t → _ → s → q → u → a → r → e → _ → r → o → o → t (son: fn_get_square_root)
                ├── r → e → v → e → r → s → e → _ → s → t → r → i → n → g (son: fn_reverse_string)
                └── s → u → b → s → t → i → t → u → t → e → ... (son: fn_substitute_string_with_regex)


logits → [2.3, 0.1, -1.5, 5.8, -0.2] gibi, 151.643 elemanlı, her eleman bir float (skor). 
Bu listenin indeksleri (0, 1, 2, 3, 4, ...) aynı zamanda token ID'lerine karşılık geliyor.
